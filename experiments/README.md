# Experiments

One script per modelling decision, so every number a decision cites can be re-run (phase 10, item 3.1; before this, PROGRESS.md often said "scratch scripts weren't kept").

Each script runs candidates through the same walk-forward as the shipped models (`src/models/compare.py`), prints the comparison and records it in `src/models/saved/leaderboard.json`. Rules (AGENTS.md "Evaluate honestly"): a choice is made on the tuning-window races; the held-out races and their race-level 95% interval only check it. A winner is switched on in `src/models/saved/model_specs.json`, which `src/models/train.py` reads.

Run from the repo root after `python -m src.features.build_dataset`, e.g. `python -m experiments.two_part_race_time`. Walk-forward predictions are cached in `data/processed/candidates/` (gitignored); pass `--fresh` to recompute.

| Script | Question | Outcome |
|---|---|---|
| `two_part_race_time.py` | Gap to the winner: one regression, or "lapped or not" then a regression per part? | Probability-weighted two-part model **shipped**: tuning-window MAE after qualifying 0.512 vs 0.527, better at every stage; held-out intervals straddle zero (0.650 vs 0.657 after qualifying). The hard switch was worse (a wrong guess costs a lap). |
| `ensemble_xgb_lgbm.py` | Does averaging XGBoost with LightGBM beat XGBoost alone? | **Shipped** for finishing position (LightGBM weight 0.7; held-out before practice 3.574 vs 3.605, interval below zero) and qualifying (0.45; held-out after practice 0.731 vs 0.740, interval below zero). Places gained: no gain, stays XGBoost. |
| `measured_circuit_facts.py` | Longest straight, braking zones and pit loss measured from F1 telemetry and MultiViewer (`features/circuit_telemetry.py`) instead of hand-typed? | **Not shipped** (2026-10-20): worse on the tuning races for every model and stage (finishing before practice 2.620 vs 2.609, qualifying after practice 0.737 vs 0.733, gap to the winner after qualifying 0.521 vs 0.517); held-out mixed, no interval clear of zero. The measured values are shown on the race page only. |
| `circuit_history.py` | Circuit facts measured from earlier races instead of hand-typed? | **Shipped** for finishing position and places gained (better on tuning races, held-out level); qualifying and gap to the winner keep the typed facts (measured ones worse on both windows). |
| `weather_lead_time.py` | Forecasts matched to each stage's lead time (3 days before practice, 1 day on Saturday)? | **Shipped** as a train/serve fix: held-out level or slightly better everywhere (finishing after qualifying 3.186 vs 3.189, interval below zero; gap to the winner 0.649 vs 0.657). The tuning window has almost no 2024+ races, so it couldn't choose. |
| `practice_pace.py` | Practice pace per session (weighted FP1 1 / FP2 2 / FP3 3, or the latest session) instead of one best lap across sessions? | **Not shipped**: qualifying worse on the tuning races with both (0.743 / 0.749 vs 0.734 after practice); session-weighted clearly worse for finishing position held-out (interval +0.003 to +0.022). Dropping track-limits-deleted laps is untested: it needs race-control messages the cache doesn't hold. |
| `router_classifier.py` | Chat routing: keyword rules, or a TF-IDF + logistic-regression classifier trained on the training conversations (labelled by the first lookup the teacher chose)? | **Classifier shipped** (2026-10-19): on held-out free-form questions 91.5% right vs 53% for the rules, and confidently wrong 2.8% vs 44% (history questions with "win" got the weekend forecast). Vetoing the rules with the classifier was worse than the classifier alone; 3k features beat 6k-20k. `--export` writes `src/agent/router_model.json`. The keyword baseline is read from git (commit 5ece5d3). |
| `retrieval_eval.py` | Does the knowledge search return the right Wikipedia page? Labels: the page of the driver, team or circuit a question names. | BM25 finds it in the top 5 for 80% of questions (first for 70-73%), raw questions and teacher-written queries alike. **Rules** (2026-10-21; labels: the article a checked answer cited, only 23): the teacher's keyword query finds it in the top 5 83% of the time (first 52%), the user's raw casual question 61% (26%): wording like "ballast" for "minimum mass". The chat model writes keyword queries, so it is fine; the no-model router, which searches the raw question, is weaker. **No embeddings for now.** |
| `router_paraphrases.py` | The classifier learned from tidy generated questions: does it hold up on unusual wording, and do reworded training questions fix that? (2026-10-21) | DeepSeek rewrote 2,976 training questions three ways (casual/misspelled, indirect, second-language or slang; 8,933 rewordings, $0.31), split by source question. On reworded test questions, fixed questions recognised **18% -> 65%** (accuracy 51% -> 78%); on the original free-form questions accuracy held (91.4% -> 91.7%), confidently wrong 2.5% -> 3.8%. **Shipped** (`--export`); the no-model threshold was re-tuned to 0.3, and a short "and ...?" now follows the previous question first. |
| `quali_chained_target.py` | Qualifying: learn from a session-chained gap (each driver against the fastest car of their last session, plus that car's own gap) so a Q1 exit isn't charged for track evolution? (phase 10 item 1.6, 2026-10-21) | **Not shipped.** Chained and official gaps differ by 0.67 points on average, and the evolution is predictable: slower cars go out earlier and always carry it. Trained on the chained gap and scored on the official one the app shows, the ensemble is worse on the tuning races and held out (before the weekend 0.805 vs 0.773, after practice 0.761 vs 0.722, both intervals above zero). |
| `title_odds_backtest.py` | Title odds: each driver's strength at each remaining venue instead of one strength for the season, and/or each team's form drifting round to round? Backtested after every round of 2023-2025 with nothing from after the round (model refitted, venue inputs rebuilt) (phase 10 item 2.5, 2026-10-21) | **Neither shipped.** Drivers' champion log loss: venue strengths won the choosing seasons 2023-24 (0.143 vs 0.149) but lost the 2025 check (0.940 vs 0.915); drift made drivers worse everywhere. Drift halved the constructors' error in 2023-24 (1.42 -> 0.70, McLaren's mid-2024 rise) and hurt in 2025 (0.05 -> 0.20). Three seasons (2022 lacks sprint results) are single-season stories, not evidence. **Shipped instead:** FIA countback for ties (a rules fix). The simulator keeps both options (`drift`, a per-round strength matrix) for a re-run with more seasons. |
